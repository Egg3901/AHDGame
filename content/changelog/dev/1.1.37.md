Cut from development.

## Operating cost survived a retool. It should not.

When a plant changes recipe, output units change meaning: a coal unit and a
rare-earth unit are not the same thing. The player command already moved the
calibrated leftover operating cost by the inverse of that ratio, so the
actual bill stayed the same. Automated retools (NPC miners, shortage
conversions, input-squeeze shifts) moved plant size and the build queue but
left that residual on the old unit basis. The next physical P&L then charged
the old per-unit leftover times the new unit count.

Every automated path now uses the same helper as the player command. Total
physical opex is invariant across the mix change. In-flight auto-retoools
that still have a transition marker are rebasing on the next sector turn;
there is no production data rewrite.

## Miners score the market they actually sell in

The extraction auto-pass was still reading the planet-wide price. In a
partitioned world that can point a miner at a shortage it cannot reach, and
the generic (non-extraction) half of that pass started a 24-turn cooldown
on those global scores before the NPC brain could re-score the same sector
on reachable prices. The generic half is gone: non-extraction retools stay
with the NPC input-squeeze pass, which already uses reachable prices.
Extraction re-strategize now uses the host country's reachable book,
falling back to national then global.

## What this is not

Player-run farms and plants are not auto-retooled. A strategy you set stays
until you change it. NPC recovery is staggered (one sector per corp, eight
turn cohort, twelve turn transition), so it shows up as transitions and
improving P&L, not as a single calendar turn when everything flips.
