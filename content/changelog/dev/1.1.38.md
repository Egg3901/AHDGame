Cut from development.

Reported as ticket #1117: a player relocated between states, tried to move
again, and found the button simply would not respond. No error, no toast, no
explanation.

The cooldown itself was correct and always has been. It is per character, read
off that character's own `lastRelocatedTurn`, so there was no shared-cooldown
bleed of the kind ticket #1079 hit. The defect was purely that the interface
refused to say so. A disabled button whose only explanation is a `title`
tooltip communicates nothing on mobile, where there is no hover, and reads as
a broken control rather than a rule.

The relocate status endpoint now returns `remainingTurns` alongside the day
count, so the client can phrase short waits in hours instead of rounding
everything to days. The button stays enabled while the cooldown runs, relabels
itself to the remaining time, and on tap opens a "Relocation cooldown" dialog
with the wait spelled out, rather than opening the normal confirmation flow.

Eligibility logic, cooldown length and the write path are untouched. This is a
copy and affordance change.
