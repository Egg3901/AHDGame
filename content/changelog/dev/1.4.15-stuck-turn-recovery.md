Cut from development.

## Fixed

- A turn whose process died partway through left the game showing
  "Processing..." with no way forward. Recovery depended on the turn tick at the
  top of the hour or the backup at half past, so a turn lost at five past the
  hour sat wedged for twenty five minutes and a turn lost at thirty five past
  waited most of an hour. A recovery sweep now runs every five minutes and
  repossesses an abandoned turn. It is strictly a recovery path: it will never
  start a turn that is merely due, and it leaves alone a lock held by anything
  other than turn processing, so the clock still advances only on the normal
  ticks.

- The memory ceiling for the game server was set below what a turn actually
  needs. A single turn moves roughly 440MB while the steady state already sits
  between 350MB and 660MB, so turns kept crossing the safety threshold and
  restarting the server, sometimes running out of memory outright before the
  guard could act. The ceiling has been raised so a turn has roughly two and a
  half times the headroom it was measured to use, after accounting for the
  second memory guard that now becomes the binding one. The extra room should
  also ease the garbage collection pressure that had been making turns
  progressively slower.

- The memory guard used to shut the server down without handing back the
  processing lock, turning a clean, deliberate restart into a wedged game. It
  now releases the lock first.

- A redeploy landing mid turn could strand the lock. The framework installs its
  own shutdown handler before ours and exits the process without waiting, which
  cut short the release already in flight. Our handler now runs first, so the
  lock is handed back before the process goes away. In flight requests are still
  drained normally on deploy.

## Changed

- The admin panel failed to open on Support then Logs, showing "Couldn't load
  admin panel" for the whole panel rather than an error in the one tab. Some
  admin log rows store a structured payload where a plain sentence is expected,
  and rendering one of those directly is an error React refuses to recover from.
  One such row sat in the batch the tab loads by default, so the panel failed
  every time, and neither a refresh nor resetting the turn lock made any
  difference. The payload is now shown as readable text instead of being
  dropped, guarded both where the data is served and where it is displayed.

- Turn logs and admin log rendering gained regression tests covering the shapes
  production actually stores, including phase results recorded as a plain
  true or false rather than a set of counters.
