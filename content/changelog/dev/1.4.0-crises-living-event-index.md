  Every turn, the crisis spawner tried to record new crises and failed a

  and the uniqueness rule ignores empty values.

Cut from development.

## Fixed

- Crisis records created without a living-conflict event no longer write an
  empty event marker. The driver serialized the absent id as null, and the
  unique index that dedupes replayed events keyed that null, so the second
  such crisis failed with a duplicate-key error on every spawner turn.
- The dedupe index is rebuilt as a partial unique index that only applies to
  real string event ids, so neither null nor missing markers can ever
  collide again, even if a future writer regresses.
- A migration unsets the stray null markers on existing worlds; null-valued
  markers also broke the legacy-crisis compatibility queries that check for
  the field's absence.

## Guarded

- Tests pin the writer contract (key absent without an id, present with
  one), the migration's dry-run read-only behavior, the sparse-to-partial
  rebuild, and the already-migrated no-op.
