## What changed

- The accepted `badges` and `areas` values live in one place, `src/lib/changelog/types.ts`. The loader, the CI guard, the feed's colour and label maps and the filter pills all derive from it, so a value cannot be accepted somewhere and unstyled somewhere else.
- Added `minor` as a badge and `engine` as an area. Three separate authors reached for them, and both describe things this project genuinely ships: `engine` is the hourly turn processor and the simulation phases, which is neither backend request handling nor frontend.
- `npm run changelog:new` writes the accepted values as a comment above each field, so the vocabulary is readable where it is typed instead of only in the loader. It also takes `--badges` and `--areas` and rejects an unknown value on the spot.
- A rejected value now says what is allowed. The old message read `unknown badge "minor"` and left the author to go and find the list.
- Changelog entries are checked on commit through the existing lint-staged hook, so the check only runs on commits that touch an entry. Before this, a bad value merged and then failed CI on `development`, blocking unrelated pull requests for a full build cycle each time.

## Why

Descriptive words for what a change was about, like "balance" or "bugfix", belong in `tags`, which is free text. Badges say how big a release is and areas say which part of the codebase moved.
