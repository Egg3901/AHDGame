Patch cut from development, 2026-08-13. All entries below shipped today.

## Interstate haul is now real freight demand (ticket #1039, PR #63)

The Logistics map read haul TEU from `sourcingNetworkLoad`, the record-only
landed-price sourcing ledger, while logistics sold % cleared against freight
demand that never included that haul. A state could show thousands of TEU of
haul while its logistics sectors sat in a glut. The sourcing pass's consumed
TEU per origin state is now booked as freight demand before clearing, at the
state leg (state prices and the map's stored `stateDemand`), the national
aggregate (trade clearing), and the global balance (price and sold %). Freight
is never itself shipped, so there is no same-turn feedback; higher freight
prices damp next turn's haul through shipping cost. Money wiring (who pays
shipping, plan step 5) is still off. Map copy updated to match.

## Money wiring for interstate sourcing (plan step 5, flag off, PR #69)

The landed-price sourcing pass stops being purely observational. Behind a new
gameConfig flag `interstateMoneyWiringEnabled` (default off, everything byte
identical while off):

- The sourcing pass now records, per destination state and commodity, the
  delivered units and the extra cost (shipping plus tariff) they carried, and
  per importing country the total tariff paid and import value. Both persist
  on the `sourcingNetworkLoad` doc as `landedPremiums` (per-unit surcharge)
  and `importAggregates`.
- Plants pay the landed premium: `computeInputsCost` adds the sector state's
  per-unit surcharge on top of the global lagged price ratio, so out-of-state
  sourcing costs real money. One-turn lagged like the price ratios.
- Tariff revenue becomes flow-aware with netting: the sourced import value is
  netted out of the GDP-proxy import base before the rate applies, then the
  sourcing pass's real tariff take is added on top, so sourced trade is not
  double counted. Wired through budget refresh, fiscal year, tariff bill
  enactment, tax-rate bills, and the budget detail recompute; the client-side
  estimate helper stays on the proxy with a pointer comment.

Logistics corps already earn the haul through demand wiring (previous entry),
so no separate haulage transfer exists. Rollout per the interstate-logistics
plan: flip the flag in sandbox first, then prod.

## Campaigner NPP Management was a dead letter (ticket #1067, PR #64)

PR #4318 admitted confirmed campaigners to `canUseNationalPartyInfluence`, so
the national NPPs tab and the influence GET/POST route let them in. The
executor (`validateNationalPartyInfluence`) still required chair / vice-chair /
admin, and that is the check that actually runs the action. Campaigners saw
"Only the National Chair or National Vice Chair can use party influence."

The executor now uses `isNationalCampaigner`, matching the route. Recruitment
is still chair / vice / admin. State NPP Management is unchanged.

## State Overview pool legends carry party identity (PR #67)

The Org Pool and Registration Pool legends listed bare abbreviations against a
colour dot, so a state page gave no way to read a party's actual name without
leaving the tab. `PartyOrgRow` and `registrationPool.parties` now carry the
party's full `name` from `politicalParties`, and both legends render through a
shared `PoolLegend` component: party logo, full name, abbreviation as a muted
tag, then the share. Non-party buckets (Unaffiliated / Independent /
Unregistered) have no party doc, so they keep the plain colour dot. The name
truncates with a `Name (ABBR)` tooltip on narrow cards.

## Whips no longer sign as Admin (ticket #1062, PR #58)

State-party whips never stamped issuedByRole, and the list UI resolved issuers
against the national chair, so a state chair's NPP whip rendered as "HARD FOR
by Admin". Chamber-leader roles also collapsed to Admin in the player-whip and
defiance panels. A shared issuerRole helper now infers the issuing org's chair,
and Admin only shows for a stamped admin override.

## USD equivalents on non-dollar budgets (ticket #1065, PR #62)

Soviet outlays printed as руб566B with no FX note, so a US player read it as
$565B. Alphabetic currency prefixes get a space and national budget surfaces
show an approximate USD figure from the era denomination rate.

## NPP corp budgets stop summing mixed currencies (ticket #1060, PR #53)

`CorporateSector.revenue` and `realizedRevenue` are stored in the sector's
HOST-state functional currency, the market it operates in, not the parent
corp's home currency. The NPP brain summed them straight across a corp's
sectors and treated the total as the corp's own revenue, so a multinational
added lire to yen to dollars and got a number in no currency at all. That total
then sized marketing, logistics and R&D as a percentage of it, and the
resulting budgets were charged in the corp's home currency.

A purely domestic corp was unaffected, which is why this survived so long. A
corp holding sectors abroad was not: Meyer Logistics, with an Italian and a
Japanese sector alongside four American ones, was sizing dollar overhead
against a total dominated by lire and yen nominal revenue.

`sectorEconomicToCorpLocal` now normalizes each sector's figure through its own
host-currency rate before the sum, so `totalRevenue`, `corpMargin` and every
budget derived from them are one currency. This is the same conversion the
player paths (`expandSector`, `buildCapacity`) have always done.

## NPP corp operators actually run their companies (ticket #1060, PR #59)

NPP caretaker CEOs sat on idle cash (the Meyer Logistics report) and never
touched wages, supply agreements, or prospecting: the operator passes the 1953
all-flags world runs were simply missing. New turn passes under
`src/lib/turn/npp/`: treasury (surplus parked in high-coupon home-currency
bonds via the player buy path), supply agreements (negotiated with capacity
checks through the shared `supplyAgreementCapacity` helper), prospecting, and
wage adjustment in `nppCorporationBehavior`. Wiki pages updated to match.

## State Elections is one click from the nav (PR #77)

The state menu listed Overview, Economy and Legislature, but nothing for the
state's races: reaching them meant opening the state page, then Politics, then
the Elections sub-tab. A State Elections row now sits between Economy and
Legislature and goes straight to `?tab=politics&sub=elections`. It is separate
from My Election, which still jumps to your own race. Added on all four nav
surfaces (classic and focused, desktop and mobile) with English and German
labels, and a test pins the link's URL to the tab it is supposed to open.

## Soviet bills reach the proposal command (ticket #1061, PR #55)

Bill origins were validated against a fixed chamber list rather than each
country's own configured legislature, so chamber keys that exist only outside
the US and UK were rejected before the proposal command ever ran. A Soviet
player could not submit a bill at all. Origins now validate against the host
country's legislature configuration, which admits the configured chambers
without weakening the cross-country checks that stop a member of one
legislature proposing into another.

## The status bar covered modal buttons on mobile (ticket #1061, PR #74)

The fixed bottom status bar and modal overlays both sat at `z-50`. At an equal
z-index the later element in the document wins, and the root layout renders the
status bar after the page, so the bar painted over the bottom of every modal.
On desktop the modal centres well clear of it. On a phone a tall form like
Propose Legislation fills the viewport, and its Cancel and Propose row landed
underneath the bar, unreachable: the bar is fixed, so scrolling does not move
it out of the way. The status bar drops to `z-40`, below the overlay level, and
a test now pins that ordering. This covers all 50 modals that use the standard
overlay, not just bill submission.

## The repo typechecks again (PR #80)

`tsc --noEmit` had been failing on `development` since 2026-08-12, and nothing
caught it because the GitHub Actions `verify` job cannot start while the
account's billing is unresolved. Four errors across two files, all type-level
with no behaviour change:

- `statePartyElections` filtered residents with `$nin: [null, ""]` on `party`,
  which is typed as a string. The runtime filter is correct, because characters
  written before the field became non-optional persist `party` as null, so the
  array is cast rather than narrowed. Dropping null would have counted

- The `heal-npc-household-bulk-books` migration referenced an `ActiveBankRow`

  `.project()` calls, and typed the `gameState` singleton without its literal
  string `_id`.

## NPP corp cash rails re-based for 1953 (PR #73)

The companion to the entry above: the operator passes exist now, but the rails
they spend against were still modern-era. `CASH_FLOOR`, `SAFE_CASH_FLOOR_MIN`
and `EXPANSION_MIN_CASH` gate every discretionary decision an NPP-run corp
makes: dividends, sector expansion, and the growth leg of capacity
reinvestment.

Measured on prod at turn 79, over a 200-corp sample of the 476 NPP-run corps:
median liquid capital ₳1,724,110 against a ₳2,000,000 floor, with 105 of 200
below it. A corp under the floor cannot spend, so it cannot earn its way back
over it, so the lockout is permanent. The symptom is a corporation whose sectors
are all healthy (20-35% margins, selling out every turn) sitting on idle cash
while its share price falls. Meyer Logistics again: ₳1,199,942 of cash, six
sectors at 21.9-37.6% margin all clearing, share price 17.35 to 4.38 across
turns 59-79.

The floor drops to ₳250,000, the safety rail to ₳125,000 and the expansion
surplus requirement to ₳625,000. The family moves by one factor, so the design
ratios are unchanged and only the scale differs. On the same sample the frozen
count falls from 105 of 200 to 36. The rest are corps that are genuinely out
of money, which is what the rail is for.

The safety rail had to move with the floor. It is a `MAX()`, so leaving it at
₳1,000,000 would have clamped the new floor back up and made the change inert.
A guard test pins that case.

A calibration, not a cure. The cohort's cash spans four orders of magnitude
(p25 ₳398,719, p75 ₳52,833,977), so no absolute number fits both tails. The
durable fix derives these rails from the corp's own revenue and the world's era
unit scale, as `computeBuildCost` already does.

## National offices survive in-country relocation (ticket #1057, PR #38)

`performRelocation` vacated every `currentOffice` on any home-state move,
including President, Vice President and cabinet. That matched state-bound seats
(governor, House, Senate) but not country-scoped ones: Central Bank Chair and
NatCorp CEO already resigned only on a country change. Same-country moves now
keep offices carrying no state residency stamp, and cross-country moves still
vacate everything. The relocate confirm dialog and the in-game wiki page were
updated to match.

## Bloc influence was priced out of its own mechanic (ticket #1064)

A point of a nation's alignment cost one percent of that nation's annual GDP.
Against the live 1953 funds that priced every western bloc out entirely: NATO's
whole treasury bought 0.76 points on the cheapest nation on the board, and the
per-nation ceiling is five a turn. No amount of saving let NATO reach the cap on
any target, so a play was never a contest, and opposing pulls only net into a
back and forth if both sides can afford to push in the same turn.

A point now costs a tenth of a percent. The same treasury buys about 7.6 points
on a small nation, so the turn ceiling binds instead of the balance, while a
large economy stays a long project: India runs about $116m per delivered point.

The tab also could not answer the questions the ticket actually asked.

- The organisation fund's balance was computed, typed and covered by a test, and
  then rendered nowhere. It now sits above the amount box, in the fund's own
  currency, next to a line naming where the money comes from.
- The costs quoted on a dossier read in the viewer's preferred currency while
  the amount box takes the fund's. Nothing said so. Everything attached to the
  box is now in the fund's currency, and the label names the currency code
  rather than the fund's country.
- Typing an amount now previews the points it buys and warns when it runs past
  the per-turn ceiling or past the balance.
- The form says the fund is debited now and the nation moves when the turn
  processes, which was the ticket's literal question.
- The tab links the world alignment wiki page, which a moderator previously had
  to paste by hand.

A play that resolves to zero is now refunded. The fund is debited a turn before
a play resolves and the command already refuses a locked target up front, so a
zero means the board moved inside that window rather than a bet that lost. Aid
rows are never refunded: their money has already gone to the recipient and no
fund was debited, so returning it would mint the amount. Refunded rows read
"refunded" in the ledger instead of "0 pts" beside a spend.

## The DD Land e2e test was asserting a rule the seeder does not have (PR #85)

`politicalLegislationReset.e2e.test.ts` asserted that every non-tax law in
every catalog has a national `statePolicies` row. Regional secondaries never
get one: `seedPoliticalLegislation` skips them explicitly, and the DD Land
sidecar's own header says they never write national policies. The assertion
had no scope carve-out, so it went red the moment a regional catalog existed.

PR #17 added the six DD Land laws on 2026-08-12 and the test has been failing
on `development`, and shipped failing to `main`, ever since, reporting a
seeding bug that was not there. The assertion now matches the seeder's real
contract, and the regional case is pinned explicitly in both directions
(type present, national policy absent) so a future change to scope handling
fails loudly instead of silently flipping the rule.

## Assign a whole military branch, and stay on the branch you were in

Assigning a Navy or Air Force unit from the defence roster reloaded the office
and dumped the branch tabs back to Ground, so assigning a fleet meant clicking
Navy after every ship. The roster now stays on the branch you picked. There is
also an Assign entire branch control that posts every unit of that branch to
one general (or back to General Staff) in a single order.

## Borrowing no longer counts as bank capital

`assessCapital` measured capital as `postedCapital + liquidCapital`. Money drawn
on the discount window is credited straight into `liquidCapital`
(`discountWindowCommands.ts:80`), and so is a CB margin draw. Both are somebody
else's claim on the bank and both counted as the bank's own capital, so
**borrowing raised the capital ratio**: a bank one draw from breaching the
minimum could cure the breach by drawing on the emergency facility it needed
because it was in trouble.

Capital is now `postedCapital + liquidCapital − discountWindow − cbMargin −
interbank`. A draw moves cash and the matching liability together and leaves the
ratio where it was.

Deposits are deliberately NOT in that line. In this engine deposits are not
cash: phase (b) of `bankingTurn` moves `npcDeposits` against the central bank's
`externalBroadMoney` and never touches `liquidCapital`, and deposit flight in
`bankSolvencyTurn` does the same in reverse. The deposit base is a liquidity
test (`reserveRatio × deposits`), not a capital test. Subtracting it here would
have reported every honestly-run bank in the world as insolvent the moment it
took a deposit.

Side effect worth knowing: loans are funded by the deposit base, so originating
one now grows the denominator and leaves equity alone. Lending costs ratio
instead of creating it.

`BankBalanceSheet.borrowings` is required rather than optional. An omitted
liability silently inflates equity, which is the bug being fixed; making it
required turned the compiler into the thing that found all four call sites.

## The reserve floor

`bankCharter.reserveFloor` (`totalDeposits × reserveRequirement − postedCapital`,
recomputed each banking turn) is enforced inside
`atomicallyDebitCorpLiquidCapital`, in the same atomic filter as the balance
check via `$expr`. A chartered bank's depositors and its shareholders share one
`liquidCapital` field, and nothing stopped the CEO spending the depositors' half
on capacity, shares, bonds or payouts. The reserve ratio was measured after the
fact, so it recorded the raid rather than preventing it.

Posted capital is netted off the floor because it is already cash held aside
behind the charter. Without that, posting capital would raise the floor by the
same amount it lowered the balance and a recapitalization could lock a CEO out
of their own treasury.

The turn engine deliberately does not route through this guard: deposit
interest, insurance premiums and loan servicing move bank cash directly. Those
are the bank meeting its obligations, not the corporation spending its
depositors' money.

## Charter type switching (PATCH .../bank/charter)

Previously the only route from a retail charter to an investment one was to
persuade the central-bank chair to revoke your charter and then charter again
from scratch, posting capital twice, which is to say there was no route, and a
player who picked wrong at founding was stuck.

Switching to a charter that cannot hold deposits returns the whole book: player
savings pointers flip back to the central bank (balances untouched, pointer
only) and NPC deposits go back to `externalBroadMoney` with conservation. That
is the real price; `CHARTER_SWITCH_COOLDOWN_TURNS` (24) only exists to stop a
bank flipping every few turns to arbitrage whichever facility is cheaper.
Refusing the switch until the CEO had shed deposits by hand was the alternative,
and there is no mechanism for them to do that (they cannot evict depositors),
so it would have reproduced the original complaint with extra steps.

Facilities that do not survive the target charter must be settled first: an
outstanding discount window blocks a move to investment, outstanding CB margin
blocks a move to retail. Loans are left in place and keep amortizing, the same
rule `unwindBank` uses.

## The household book is no longer one number

`bankLoans` gains `creditBand`. The NPC household book was a single `npcBulk`
loan with one rate and one blended default rate, which is why the console could
only say "NPC bulk outstanding (implied)": there was genuinely nothing else to
say. It is now one document per band (AAA through CCC, `creditBands.ts`), so the
same servicing loop produces a book that can be read by rating and shocked by
composition.

`bankCharter.lendingProfile` (conservative / balanced / aggressive) selects which
bands are originated into from the next turn. It never reprices, recalls or
re-rates a tranche already on the book: bands outside the stance get a target of
zero and wind down at the ordinary flow cap. A pre-split book carries no band and
is serviced as its own tranche at its own stored rate with a target of zero, so
it runs off while the banded tranches build; total book size lands in the same
place and only the composition changes.

Aggressive is a trade, not a free win. At an 8% base rate a conservative book
nets ~6.8% on 45% of household demand and an aggressive one ~6.2% on 100% of it:
more absolute income, thinner margin, and a stress loss of ~15% against ~3%.

## Stress is now band-weighted

`STRESS_LOSS_FRACTION` was flat at 15% for every bank regardless of what it had
lent into. `stressLossFraction` derives the shock from the book's band mix at
`STRESS_LOSS_MULTIPLIER` (5×) expected defaults, calibrated so an all-in
aggressive book lands on the same ~15% it always got. Aggressive banks see no
change; conservative banks stop being punished for a book they never held. A
mostly-legacy book keeps the flat fraction, blended on the banded share, so one
new tranche cannot re-score the whole book as prime.

## DD Land laws were inflating the national baseline (PR #87)

Second consumer hit by the same root cause as the reset e2e. `baselineTotals`
in the baseline fiscal calibration walks the whole law catalog and costs each
law against that country's NATIONAL bases, skipping only taxes and
zero-baseline laws. It had no regional carve-out.

PR #17 added the six DD Land laws on 2026-08-12, all at `baselineLevel` 3, all
`allowedScope: "regional"`. Land spending is not national outlays, so summing
them pushed DD's baseline 3.3pt away from the design doc's figure against a
1pt pin, and the test has been red on `development` and on `main` since. With
the carve-out applied, DD lands back on the doc's number, which confirms the
regional laws were the entire discrepancy.

The lesson generalises: adding a regional catalog silently broke every
consumer that assumed "catalog entry" meant "national law". The seeder had the
carve-out, its unit test had it, the reset e2e and this calibration did not.

## NPP corporations can finally see their own debt (PR #88)

The NPP corporation brain had no concept of debt. A grep for "bond" over
`nppCorporationBehavior` returned zero hits, so the signal it judges itself on
(`totalIncome`, `corpMargin`) counted sector income and discretionary overhead
and nothing else. Bond interest is not discretionary and is routinely the
largest line on a levered corp's books.

Prod corp 446, Meyer Logistics, at turn 79: revenue 30,463, total costs 25,123,
operating profit 5,340, bond coupon income 386, bond interest expense 6,390,
net income -664. Six sectors at 21.9-37.6% effective margin with five of six
selling out. Nothing was wrong with the business. The caretaker CEO read it as
profitable for twenty turns, kept paying full marketing and R&D, never
deleveraged, while the share price fell from 17.35 to 4.38.

Two figures were disagreeing and both were right about different things:
`income` on the Financials tab is `afterTaxOperating - dividends`, which
excludes bond legs because they settle in the bond phase, while the share price
is driven by `earningsHistory`, which is net income INCLUDING them. So the page
said profitable and the chart said dying.

`perTurnIssuerBondInterestExpense` and `perTurnBondCouponIncomeAsHolder` move
out of `sectorCalculations` into `src/lib/bonds/corpBondCashflows.ts` so the
brain reads the exact numbers the turn engine bills, rather than an
approximation. The brain now loads the same issuer and holder bond maps
`buildCorporationLookups` builds, nets them per corp, and subtracts the result
before judging profitability. National enterprises keep their issuer-interest
waiver, matching `perTurnBondDragOnNetIncome`.

This is the third time this module has been fixed for the same class of bug: it
read the seeded `profitMargin` instead of the effective one, then nominal
instead of realized revenue, now operating income instead of net. Each time the
signal was stable and wrong, so the AI confidently did the wrong thing.

Groundwork for the adaptive NPP brain: a strategy that switches when it is not
working is worthless while every strategy is scored on a number that omits the
cost doing the damage.

## The bank console was one 2,300 line file (PR #90)

`BankConsoleTab.tsx` sat over both architecture caps: 2,297 lines against a 2,000
line cap, and 17 `useState` calls against a cap of 15. It was over both on `main`
before the banking-integrity work touched it, so this is accumulated drift rather
than a new regression.

It is now a directory. `types.ts` holds the `ConsolePayload` contract the console
API fills. `lib/helpers.ts` holds the three things the panels share: the
`mergeState` reducer body, `charterLabel`, and `partyHref`. `components/` holds
the pieces used by more than one panel (`PartySearch`, `StatCell`,
`BlacklistChip`). `sections/` holds one file per panel: health, charter issue,
rate offsets, loan book, blacklist, capacity allocation, discount window,
recapitalization, prop book, interbank, and charter revocation. The entry file is
113 lines and does one job, which is load the payload and pick between the issue
form and the active charter panel.

Two panels moved to `useReducer` on the way, matching what the rest of the console
already did. The prop book kept four separate pieces of state for one form whose
fields clear together on a successful open. The interbank panel kept five across
two desks that share a single in-flight flag. Both are one state group now.

No behaviour changed. Same endpoints, same request bodies, same validation, same
effect order. Structure only.
