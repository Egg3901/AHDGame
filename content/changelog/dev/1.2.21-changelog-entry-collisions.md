Cut from development.

## Changed

- Developer changelog entries are named `<version>-<topic>.md` instead of
  `<version>.md`. The topic is the ticket or branch the entry belongs to, so two
  branches cut on the same day write two different paths and git merges both
  without a conflict.
- Nothing reads the version out of the filename. Ordering and grouping have
  always come from the frontmatter `version` and `date`, and the feed keys on
  the filename stem, so the version number stops being a first-come claim.
- Public entries keep the bare `<version>.md` name. That stem is the published
  URL at `/changelog/<version>` and is listed in the sitemap, and public entries
  are written once per release by one author, so they never race.
- `npm run changelog:new -- "Title"` writes a correctly named entry, defaulting
  the topic to the current branch and suggesting the next unused version.

## Fixed

- Two developer entries, 1.2.4 and 1.2.8, were left with unterminated
  frontmatter and no body by an earlier conflict resolution. Both parsed as
  nothing and never appeared in the feed. Restored, with 1.2.8 no longer
  carrying 1.2.4's title.
- Entries carrying badge and area values outside the supported vocabulary
  (`balance`, `bugfix`, `fix`, `feature`, `minor`, `engine`) now use the values
  the renderer actually understands. These were being dropped silently, so
  nothing on screen changes.

## Guarded

- A test over `content/changelog/` fails the build if two entries claim the same
  slot, if a filename and its frontmatter disagree on the version, if a new
  developer entry uses the bare `<version>.md` name, or if required frontmatter
  is missing.
