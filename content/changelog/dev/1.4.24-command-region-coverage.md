  Pairing a Logistics command with the Regional command already holding a region

Cut from development.

## Fixed

- A region covered by two commands of different types reads as ASSIGNED instead of
  UNASSIGNED. Coverage counted a region as covered only when exactly one command
  claimed it, so the supported pairing of a Regional and a Logistics command fell
  past every branch and landed on UNASSIGNED. Because coverage is the default view
  in the region list, the builder was reporting the correct structure as a gap, and
  the same region also turned up under the uncovered filter as work still to do.
  Nothing was wrong with the saved commands: both held the region the whole time
  and the Logistics command was delivering supply there.

- The create dialog no longer warns that a region is already assigned when the
  command holding it is of a different type. Only a second command of the same type
  is a role conflict, which is the line the overlap check has always drawn, but the
  warning ignored type entirely and fired on any owner. The message now names the
  clash as a same type one so it is clear what the objection is.

## Changed

- The Military Commands wiki page said a region should be covered by exactly one
  Command, three lines above a bullet explaining that only two commands of the same
  type conflict, and further above a walkthrough recommending a Regional and a
  Logistics command for an overseas fight. It now says one Command of each type and
  states plainly that the Regional and Logistics pairing is the standard setup.
