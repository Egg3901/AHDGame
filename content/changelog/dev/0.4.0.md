### Commodities & corporations (`marketSystemMode` graduated tiers)

- **Realization** — `computePriceRealization` on sector revenue (`src/lib/market/priceRealization.ts`).
- **Ledger / clearing / capital** — flow ledger, inventory, posted-price clearing, capacity & unit economics (built 0.3.6 merge; flip via `GET/PATCH /api/admin/config/market`).
- **Clearing-collapse remediation + launch-safety governor (pre-go-live hardening).** A t879 clone A/B surfaced a −67% collapse, root-caused and fixed across five commits on `fix/clearing-orderbook`:
  - **Offered-book reconciliation** — the clearing order book derived offered units from `revenue/basePrice`, which equals physical units × priceRatio and inflated the book for above-base commodities; the FX leg further inflated JPY/NGN books ~100×. Offered units are now normalized down to the lagged physical supply ledger (`clearing.ts`), so corporate mean `soldFraction` tracks the true clear rate (~0.92) instead of a phantom 0.13.
  - **Launch-safety governor** (`softenedMarketRealization`, `src/lib/market/capital.ts`) — the clearing/throughput revenue legs are bounded to within ±`marketGovernorCap` (default 0.15) of the ledger baseline and ramped in from 0 over `marketGovernorRampTurns` (default 240), so enabling clearing/capital is a **no-op on the flip turn** and valuations drift rather than crater. Both tunable live via `PATCH /api/admin/config/market`.
  - **Capital book-value floor** (`capitalBookFloorNpv`) — capital-mode sectors convert earnings into productive `capitalStock` but tangible book only credited `sectorNPV` (a perpetuity on current profit → 0 when transiently depressed), so investing corps were valued as if they owned nothing (a systemic ~25-33% mcap gap vs ledger, broad across all countries). Book contribution is now floored at the normal-margin going value of owned capacity via `max(sectorNPV, floor)`; tunable via `marketCapitalBookFloorMargin` (default 0 = inert).
  - **Auto-revert launch guard** (`src/lib/market/launchGuard.ts`, opt-in `marketGuardEnabled`) — each turn stamps a reference market cap and auto-reverts to `ledger` if aggregate mcap falls > `marketGuardDropPct` (default 0.25) after a grace window. Turns the flip into a reversible, self-flooring experiment.
  - Findings: production/GDP reaches **parity** with ledger under capital; the gap was valuation-side, addressed by the book floor. A/B harness + methodology in `docs/plans/2026-07-06-clearing-fixed-ab-handoff.md`.
- Wiki: [Commodities](/wiki/commodities#price-realization).
- **Corp-page Commodities tab + Charts → Market Share are now live data, not stubs.** #2715 shipped both surfaces as discovery placeholders ("appears as clearing rolls out") with no data path, so the clearing go-live never populated them. New `GET /api/corporations/[id]/commodities` returns: per-turn physical **output/consumption** per commodity (recomputed from `sector.revenue × effectiveStrategyRate / basePrice`, the same math as sector-detail), a **regional (per-state) breakdown**, global **market context** (price/stock/cover from the latest `commodityFlows` ledger row), and **by-industry market share + rank** scoped to the corp's home country. Share math reuses the tested `marketShare.ts` primitives (`effectiveMarketAnchor`/`gdpDerivedMarketAnchor`), FX-normalized to ₳, so the corp page, per-sector routes, and the Discord `marketshare` command agree. Private-corp fog-of-war honored via `shouldRedactCorporation`. New helpers `corpCommodityFlows.ts` / `corpMarketShare.ts` (unit-tested); the Charts metric-pill row was de-duplicated into `ChartMetricPills`.

## Shadow ledger — Phase 3 coverage sweep (shadow-only, behind `ledgerShadow`)

- **Semantic mint/sink reasons for the top single-sided flows** — the double-emit shim used to book every counterparty-less tx row's balancing leg against `mint:/sink:unattributed`, which is what the reconciler's Phase-3 backlog ranks. `deriveFromTx.reasonForTxType` now attributes the largest flows: sovereign coupon/maturity payouts pair with holder receipts under `bond_settlement` / `bond_coupon_settlement`, and `corp_tax_paid` pairs with `gov_tax_revenue` under `taxation`; `corp_revenue` books as a `sector_revenue` mint. Drains ~7.35T ₳/run (over the 150-turn sandbox) out of the `unattributed` bucket. `src/lib/ledger/deriveFromTx.ts`.
- **State-party dues now derive** — `party_dues_received` state-scope rows carry no ObjectId `subjectId` (their `statePartyOrg` owner is keyed by a composite string, not an ObjectId), so they previously produced NO ledger entry — ~62k rows/run, the single biggest row-coverage gap. They now map to a defined `state_party:<key>` account via `meta.statePartyKey`. `state_party` is deliberately excluded from the stock-checked `REAL_ACCOUNT_KINDS` for now (its treasury is also moved by still-uninstrumented PS-investment / NPP-influence spend), so it lifts derivation coverage without manufacturing stock-vs-flow divergences. `src/lib/ledger/accounts.ts`, `src/lib/ledger/deriveFromTx.ts`.
- **Balance-snapshot party fix** — the stock-vs-flow snapshot read a non-existent `parties` collection instead of `politicalParties`, so party treasuries were never captured (national party legs could never reconcile). `src/lib/ledger/balanceSnapshot.ts`.
- Still shadow-only; no enforcement/blocking (Phase 4). No game-behavior change.

## Approval / persuasion balance fixes (ticket 921)

Forensics on a live case — NC governor Bill Steinman, 89 personal favorability, losing his re-election ~49.8–50.2 to a socialist — traced four separate defects that systematically penalize aligned/right governance. Issues #2897 / #2898 / #2899.

- **Incumbency curve recalibrated (the biggest hit).** `INCUMBENCY_APPROVAL_PIVOT` 50 → 43. Government approvals cluster below 50 (national mean ≈43), so the old pivot made incumbency a _systemic drag_ for nearly every incumbent — the opposite of a real incumbency advantage — and hit popular governors whose government approval trails their personal favorability. Also made the curve symmetric: `INCUMBENCY_DRAG_MAX` 0.15 → 0.10 (no reason a penalty should exceed the shield). Steinman's incumbency driver goes from −4pp to ≈+3pp. `src/lib/electionEngine/persuasionDrivers.ts`. **Balance change — sanity-check the pivot; ideally national-average-relative at runtime (follow-up).**
- **Two mis-signed axis metrics (#2897).** `stateMediaControl` and `incarcerationRate` were `social:+1` (authoritarian-weighted) but are lower-is-better libertarian goods → `social:-1`. As written they punished an auth-right governor's own base for reducing media control / incarceration. `src/lib/utils/metricAxisAffinity.ts`.
- **Archetype-approval sign flip (#2899).** A missing prior policy defaulted `oldPolicyIndex` to a hardcoded `3`, out of bounds for any <4-option legislationType — dropping `calculateShiftImpacts` onto the legacy bare-index path that inverts every archetype-approval sign for right→left-ordered option sets (the bug that left Steinman's conservative base disapproving him). Now clamps to the type's real option-count center. Fixes 40+ residual non-US tax/economic types; the tax-bracket case was already fixed in `625c43b81`. `src/lib/billEnactment.ts`.

Not included (need a balance/design pass): a base governor-lean ↔ electorate-lean approval term (#2897 — approval currently rewards only metric out-performance vs the national average, so an aligned governor at par earns nothing), and relaxing the right-coded approval-badge thresholds that sit above their metrics' generative ceilings (#2898). A one-time recompute of already-corrupted `archetypeApprovals` + per-turn decay is scoped on #2899.
