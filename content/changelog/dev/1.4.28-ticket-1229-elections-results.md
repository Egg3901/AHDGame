## Added

- `GET /api/public/v1/elections?country=CODE` accepts `results=true`, which adds
  a `results` object to every race in the response: `{ totalVotes, finalized,
candidates[] }`, with each candidate carrying `characterId`, `characterName`,
  `party`, `votes`, and `sharePct`, leader first. A bot can now pull a whole
  country's seat-by-seat numbers in one request instead of a `/elections/[id]`
  call per seat (ticket #1229).
- The standings come from the vote tally the list query already loads, so the
  richer payload costs no extra database work.

## Unchanged

- Without `results=true` the response is exactly as before, so existing callers
  are not affected.
- Turn-by-turn vote history and primary snapshots still live on
  `GET /api/public/v1/elections/[id]`; `results` is the current standings, not
  the full time series.
