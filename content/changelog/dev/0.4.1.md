## Brand loyalty (`brandLoyaltyEnabled`, slice via `brandLoyaltySliceEnabled`)

- **Loyal slice** — up to `LOYAL_POOL_FRACTION` (0.40) of each market's demand is reserved for loyal customers and filled at the seller's posted price _before_ cheapest-first clearing. Corps split the pool in proportion to their loyalty **relative to each other**, so a universal max is equivalent to no advantage. Loyalty below `SLICE_NOISE_FLOOR` (5) gets no slice.
- **Per-turn accrual/decay** (after clearing, norm EMA updated last):
  1. Gouge check first — `posture − norm > GOUGE_JUMP` (0.08) → `loyalty −= DECAY_GOUGE` (10 one-time), skip accrual.
  2. Erratic drift — `|posture − norm| > CONSISTENCY_BAND` (0.04) → `loyalty −= DECAY_ERRATIC` (1.0, ×0.5 if downward).
  3. Under-delivery — `fill < 0.35` → `loyalty −= DECAY_UNDERDELIVER` (1.0), stacks with erratic.
  4. Accrual — contested (`CONTEST_GAP` 0.05) AND within band AND `fill ≥ 0.5` → `loyalty += ACCRUAL_RATE` (1.0; ~2 game-years to Iconic).
  5. Idle drift — neither accrued nor penalized → `loyalty −= DECAY_IDLE` (0.25).
  6. Clamp [0, 100]; `POSTURE_NORM_ALPHA` 0.1 (~10-turn price-identity memory).
- **Relative loyal-slice payoff** — loyalty only pays when it exceeds rivals'; monopoly turns don't accrue (nothing contested).
- **Gouging penalty** — a sudden reprice above the corp's own norm is the single biggest hit (`DECAY_GOUGE`), wiping ~10 turns of trust; discounting is penalized only lightly.
- **Facility-loss / Boeing rule** — losing a sector (sold/taken/closed/nationalized) hits brand proportional to the sector's weight, scaled by `FACILITY_LOSS_FACTOR` (1.0).
- **Hidden number, five labels** — players see `Unknown / Emerging / Respected / Trusted / Iconic` only (bands 0/20/45/70/90). Exact value is admin-only; never serialize the number to non-admin clients. Rivals see only the tier.
- **Rollout gates**: A1 48-turn shadow accrual (verify P10/P50/P90 spread, not uniform) → A2 150-turn A/B (premium corps profitable, volume-corp fills not degraded >5%, no regression).

## Output quality (`sectorQualityEnabled`)

- **Four pillars, geometric blend** — `quality = tech^a · inputs^b · wages^c · operations^d`. Pillars **substitute, not gate** (bad inputs pulled back up by tech/wages/operations — the "Toyota from ordinary steel" case). Tech is the primary driver; wages anchored at `wageLevel 1.0` = neutral, giving the pure-cost wage slider an upside.
- **Differentiated sectors only** — manufactured/consumer/services. Raw extractables carry no quality (fungible; a mine's "quality" is delivery reliability, already covered by loyalty).
- **Propagation** — quality flows up the chain: a chemical corp's quality lifts the fertilizer it makes, raising the ag corp's crop ceiling, inherited by the food corp, on up to demographic buyers. A corp reaches a target quality by its **cheapest path**.
- **Display** — per-sector, rolled up to `corporations.averageQuality` (revenue-weighted mean), stored raw each turn in the existing `corporationHistory` snapshot (no new collection), shown normalized 0–100 on the corp header and charts. Quality is **visible** (unlike loyalty's hidden 5-label). Adds `averageQuality` to the ChartMetric union, `CHART_METRICS` in `ChartsTab.tsx`, the `/api/corporations/[id]/history` projection, and `CorpHistoryPoint`.

## Supply agreements (`supplyAgreementsEnabled`)

- **Bilateral commodity contracts** — supplier ↔ buyer, per commodity, both-consent (offer → accept, cancellable), volume-capped.
- **Clearing order**: contracted → loyal-slice → cheapest-first. A's supply fills B's demand first up to `min(A.supply, B.demand)`; A's excess flows to open market; B's unmet demand falls back to market; no penalty if A has no supply (B just buys on market).
- **Price band** — agreed price constrained to `±35%` of prevailing market (`PRICE_BAND_PCT = 0.35`), so a contract can't be a disguised gift or gouge; moves with the market.
- **Exclusive-capable** — exclusivity + scarcity can let a pair corner a commodity; the dumping/shortage Watchtower dials cover the symptom.
- **Loyalty interaction** — contracted sales guarantee fill for the supplier (helps delivery → loyalty via Package A rules, no separate bonus) and a stable input for the buyer.
- **Implementation** — new `supplyAgreements` collection, clearing pre-pass hook, create/accept/cancel API, lifecycle management UI. C0 verification gate: UI must render correctly before any player-facing flip — treat missing/wrong surfacing as a release blocker.

- **Fix: high-inflation currencies now depreciate — no more static-peg carry (#3064, Phase 2).** `computeMacroTarget` returned the base rate unchanged for any currency absent from `ECONOMIC_BASELINES` — which includes the forex-active carry currencies IT/ES/SE/TR/FR/RU. - **Fix: savings interest now pays the REAL rate, closing the multi-currency carry trade (#3064, Phase 1).** Savings previously accrued `½·nominal-prime` APY in local currency, minted and unfunded, while the FX engine never depreciated high-prime currencies to offset it — so parking cash in high-nominal-rate currencies (NGN 11.9%, ITL 12%, SEK 9%, BRL 8.8%) was a free real return. One player (char 129) had compounded this to ~123B ₳, holding 99.97% of China's / 99.98% of Brazil's / 100% of Sweden's & Italy's entire national savings pools. `computeSavingsInterestForTurn` now takes local inflation and pays `½·max(SAVINGS_REAL_RATE_FLOOR_PERCENT, prime − inflation)`; the accrual pass (`savingsInterestTurn.ts`) and NPP mirror (`nppSavingsInterest.ts`) read live inflation from `centralBanks.inflationHistory` (same source `forexTurn.ts` uses — no new plumbing). The floor (0.5pp real, applied uniformly so it grants no cross-currency advantage) keeps low-real-rate currencies from paying literally nothing. Display APY (`loadSavingsApyByCurrency` + both central-bank routes) now shows the same real rate it pays, so quotes don't overstate returns. On current prod data this roughly halves the worst offenders (NGN 5.96%→2.75%, BRL 4.41%→2.60%). **Note:** a residual carry remains where realized inflation sits below the seeded prime (ITL still ~4.75%); fully closing it needs the Phase 2 FX-depreciation (UIP) change. New `savingsApyPercent` unit tests cover the real-spread and floor.
- **Fix: Build Org PS cost no longer stuck at the 8 max for days (#945).** The per-(party, geography) pressure ladder that escalates state-action PS cost had no ceiling on its _stored_ value — every spend did a raw `$inc: +1` while decay only removes `PRESSURE_DECAY_PER_TURN` (3) per turn. A party that built heavily in a state ran the stored pressure far past the point that already maxes the cost (base 1 + pressure 7 = the `PRESSURE_LADDER_MAX_COST` of 8): observed values of 29 (the reporter's Reform Party in Florida) and 219 elsewhere, which then stay pinned at max cost for dozens of turns after the party stops — hence "Florida PS cost is always 8, for days." The stored value is now clamped to `PRESSURE_LADDER_MAX_VALUE` (= 8) on write, so the ladder is still fully punishing while active (enough to saturate every action's cost) but decays back to normal within a few turns of inactivity, as the decay model always intended. The pressure upsert switched from `$inc` to a clamped `$set` (the tiny concurrency window can at worst under-count by one increment, harmless given the cap). Existing runaway rows on live data are clamped to the ceiling in a one-time heal.
