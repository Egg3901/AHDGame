# A House Divided — Design System

The agent-portable design-system reference. Read this before any UI work
instead of re-deriving conventions from `src/app/globals.css` or the
component tree. Token and component sections are generated — run
`npm run design:build` after changing `src/app/globals.css` or
`src/components/ui/` (lint-staged also does this on commit).

Token SSOT: `src/app/globals.css`. Component SSOT: `src/components/ui/`.

## Hard rules

1. **Semantic tokens only.** Never hardcode colors, shadows, or font sizes —
   every visual value must come from a token below so all 11 themes keep
   working. If a raw value is genuinely required (charts, maps, canvas,
   third-party), isolate it and comment why.
2. **No new font families.** The stacks are `font-sans` (Geist),
   `font-mono` (Geist Mono), `font-serif` (Lora), `font-display` (Fraunces).
3. **Reuse before creating.** Check the component inventory below and nearby
   pages before writing a new component.
4. **Density by surface.** Game overview pages can be visual; admin and
   operational pages stay dense and scannable.
5. **Every interactive surface handles loading, empty, disabled, and error
   states.**

## Token reference

Hierarchy: **brand tier** (the 11 themes, each a full palette) → **semantic
tier** (`--color-*` etc., what components consume) → **component tier**
(variant maps inside components, e.g. `Button`'s `variantStyles`).

Opacity modifiers such as `bg-primary/10` and `border-primary/30` are fine.

### Typography scale

| Class                              | Use                              |
| ---------------------------------- | -------------------------------- |
| `text-body-xs` / `text-body-sm`    | Labels, metadata, badges         |
| `text-body` / `text-body-lg`       | Normal and prominent body text   |
| `text-heading-sm` / `text-heading` | Panel and section headings       |
| `text-heading-lg` / `text-display` | Page-level titles or true heroes |

Use the display scale sparingly; compact panels use smaller headings that fit
their container. Ensure labels and button text fit at mobile widths.

## Layout patterns

### App shell and constrained content

```tsx
<div className="mx-auto max-w-7xl px-4 py-6 sm:px-6">{/* content */}</div>
```

Add bottom padding for the status bar only on page shells that can be clipped
by the fixed footer/status UI. Do not blindly add `pb-16` to nested panels.

### Cards and panels

```tsx
<div className="rounded-lg border border-card-border bg-card p-4 shadow-card">...</div>
```

Use cards for repeated items, panels, modals, and framed tools. Avoid nesting
cards inside cards unless the local page pattern already does it. Interactive
cards may use `card-hover` only when actually clickable.

### Hero headers

Some country and overview pages use an image hero with a stats strip
(`HeroStatsStrip`). Follow that pattern when editing those pages; use a hero
only when it identifies a country, institution, place, or major game object.
Operational tools and admin pages stay dense — no hero.

### Status color pattern

```ts
const colorMap = {
  success: { bg: "bg-success/10", border: "border-success/30", text: "text-success" },
  warning: { bg: "bg-warning/10", border: "border-warning/30", text: "text-warning" },
  error: { bg: "bg-error/10", border: "border-error/30", text: "text-error" },
  info: { bg: "bg-info/10", border: "border-info/30", text: "text-info" },
  primary: { bg: "bg-primary/10", border: "border-primary/30", text: "text-primary" },
};
```

## Component authoring rule

Compose component styles in this order, each layer overriding the previous:
**Base → Variants → Sizes → States → Overrides** (`className` prop last).
`Button.tsx` is the reference implementation of this pattern.
